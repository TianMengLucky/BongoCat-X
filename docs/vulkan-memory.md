# Vulkan 内存与异步生命周期

本次改造在 dev 上保留稳定插件 ABI 和 Rust 不可信数据解析。源代码没有
发现逐帧无界增长的回读队列；原实现是单份全帧缓冲。因此不将内存读数
超过 100 MB 直接归因于回读泄漏，也不承诺整机占用降至 30–50 MB。

## 固定槽与同步边界

- 主机有两个独立帧槽，各持有一个命令池、初始化/帧末命令和完成 Fence。
  推进只使用 0/1 环形下标。复用槽位前等待它的 Fence，再重置命令池并
  释放命令池内部空闲存储，不随运行时间新增命令池或同步对象。
- 帧末回读与图像转换提交异步返回。CPU 读取 RGBA/BGRA 时才等待写入帧
  的 Fence。普通交换链使用至多两份回读映射；Windows 分层窗口逐帧
  消费当前像素，复用一份映射，写入前等待前一个写入者。
- 回读有效负载为 W × H × 4 × 槽数，另有驱动对齐开销。
  同尺寸直接复用；尺寸变化清理旧大小映射；同尺寸交换链重建保留池。
- Present 信号量按交换链图像分配。帧 Fence 只证明命令执行完成，不能
  证明呈现已消费信号量；再次获取相同图像才允许再次使用该信号量。
  依据：[Vulkan 官方说明](https://docs.vulkan.org/guide/latest/swapchain_semaphore_reuse.html)。
- 队列 Fence 检查点替代正常路径中的 vkQueueWaitIdle。共享背景修改、
  失败恢复必须先同步；交换链重建和最终销毁保留设备 idle 等待。
- 已提交标记仅在 vkQueueSubmit 成功后设置。提交失败后不等待尚未提交
  的 Fence；等待失败后停止资源复用，不提前销毁未知完成状态的 staging。

## 插件资源

Live2D 使用两个上传批次槽，保留批次命令和 staging 到各自 Fence 完成；
继续限制每批 32 条命令/约 16 MiB，单张大纹理可以超过该字节阈值。
完成的 staging 在下一次绘制检查时也会回收，无需等待交换链重建。
绘制提交返回时不等待完成；下次修改几何、遮罩、描述符或 SDK 命令缓冲
前等待绘制 Fence。多 pass 复用同一套资源时仍需在复用点等待。

Inox2D 使用两个独立提交池和 Fence。纹理 staging 留在对应槽；绘制的
描述符池、uniform/vertex buffer、framebuffer 保留至下次修改前的 Fence
等待结束。错误路径放弃未提交的命令，不再自动提交半成品。
默认分配块从设备 16 MiB/主机 8 MiB 改为分配器支持的最小 4 MiB/4 MiB；
显式大分配仍是 64 MiB/16 MiB。块大小是分配粒度，不是总内存上限。

为压缩重资源，模型保留一套共享几何/中间目标/次级录制资源，下一次
改写前等待。这允许提交后 CPU 继续处理逻辑，但不声称同一模型的两帧
可以同时访问共享可写资源。主机两帧槽与模型资源集合是不同的生命周期。
旧插件宿主的同步 one-shot 服务语义保持不变；内置插件用自身异步槽，
避免旧插件仍在提交返回后释放 staging 时产生兼容性事故。

取消加载、替换正在使用的图像、重建共享目标及销毁插件是同步边界。
CPU 解码像素复制到 staging 后可以释放；GPU staging 必须等待 Fence。
不按“过一帧就安全”推断完成，也不依赖复杂退役队列或递增帧号。

## 其他内存优化

音频声部共享同路径不可变 PCM，各自保留独立游标，最后一个声部卸载后
才释放 PCM。Windows 不再由轮询主动打开音频设备，空闲 5 秒卸载引擎。
长音频仍全量解码；不同文件各有 PCM，声音首次恢复可能有设备启动延迟。
贡献者数据按关于页请求，离页取消任务并释放资源；封面纹理离模型页释放。
模型质量、平台支持及用户配置的显式大分配选项保持原行为。

## 测试方式

自动化用例 vulkan-fixed-slots 使用模拟分发，对 100 次槽循环验证数量
有界、提交时无 CPU 等待、按图像选择呈现信号量、失败后不等待空 Fence，
以及 staging 在等待成功之前不会销毁。audio 使用离线设备验证同一 PCM
共享、原声部销毁后其他声部继续有效和空闲整体释放。
vulkan-async-submission 直接链接 Live2D 提交实现，用模拟 Vulkan 验证
异步绘制、两槽上传、32 命令批次、取消、提交失败和等待失败后的生命周期。
模拟测试覆盖所有权与错误处理，不代替真实驱动验证。

手动测试建议：

1. 选择 Vulkan，切换大纹理模型、缩放窗口、连续切换纹理质量；检查画面、
   遮罩、点击命中、截图及封面没有闪烁或错帧。
2. 设置窗口及各页开关 20 次；同音效叠加触发后等待超过 5 秒再播放。
3. 关闭/移除背景、模型加载中取消或失败、插件切换及正常退出。
4. 同一模型、尺寸、质量和 Release 构建下比较工作集、私有提交、GPU
   内存、加载峰值及帧时间；用多轮稳定值判断回落和持续增长。
5. Windows 分层窗口当前帧 CPU 消费仍会等待 GPU；不要把异步提交接口
   等同于所有场景零等待。Linux 真机及其他驱动需要单独验证。

不通过强制裁剪活跃工作集制造较低读数；最终内存还受模型尺寸、纹理、
字体和驱动缓存影响。测试包不包含 Cubism SDK 或 Core，Core 由用户提供。

## 本机验证结果

Windows x64 Release 构建通过，启用 BONGO_CAT_WARNINGS_AS_ERRORS。
固定槽、异步提交、延迟管线、OpenGL 延迟着色器、SDK 补丁、字体及软件
设置界面等 7 项专项测试通过；全量 C/C++ cppcheck、行数、平台运行时
安全及原生渲染源列表检查通过。实际 GPU 与设置界面均已运行验证。

## 低内存模式

设置 → 应用新增默认关闭的开关，保存为 application.lowMemoryMode。
有效纹理画质为 min(原设置, 10%)，启用动态分辨率；原设置不改写。
Live2D 图集限制 512 像素、遮罩限制 256 像素；Inox2D 在 Rust 中
受限解码并缩小图集到同一画质和边长预算，再交给已有渲染器。
窗口尺寸及 Inox2D 整帧合成表面保留，以免改变桌宠位置和点击范围。
切换走已有后端重建/模型重载流程，释放前等待 GPU。
低内存模式暂停大块分配、Bindless 和并行录制请求；Live2D Vulkan
使用 256KiB VMA 小块子分配减少零碎专用分配，允许安全扩容。

Live2D Vulkan 管线按首次使用创建，普通模型不再预编译所有混合变体。
共享变体的首次创建由互斥锁保护，创建失败释放部分句柄并传播错误；
既有设备/录制线程等待完成后再释放管线和描述信息。此优化无需开启开关。

## 进一步收紧资源

低内存模式关闭 OpenGL MSAA，并采用表面允许的最少 Vulkan 交换链图像。
OpenGL 基础着色器（包括普通、遮罩、复制）改为首次使用才编译，
兼容加法/乘法共享普通着色器及不可变参数位置；编译失败清理中间对象。
Vulkan 再细化到具体兼容混合变体，保留固定槽和每变体就绪位。
创建失败仅销毁当前新变体，保留已使用的兄弟管线；释放仍经过原有等待。
低内存模式不保留模型行为备用副本，失效缓存立即释放。
原生背景未镜像/翻转时借用源表面，移除背景时释放合成画布。

50MB 是专用工作集的目标预算，必须区分私有工作集、总工作集和私有提交。
下文测量结果以当前机器和模型为范围，不承诺所有驱动及模型都满足。

## 设置界面及实际测量

Windows 低内存设置窗口对 OpenGL/Vulkan 均使用分块 SDL 软件绘制；
其他平台的 OpenGL 复用主上下文，Vulkan/Metal 使用软件设置窗口，避免
额外初始化 OpenGL 驱动。软件设置窗口采用不透明背景。字体图集分别
烘焙 18、20、28、36 像素字形，按屏幕 DPI 栅格化，所有文字采用 2 倍
抗锯齿采样；大标题仅收录所需字形，不通过放大正文来节省内存。
软件路径保留 A8 图集与一个可复用小字形纹理；整张字体图集不再扩展为
四通道。按完整字形/游标边界裁掉底部空行并校正 UV。字形 UV 恢复准确
纹理像素，目标矩形在物理像素空间绘制，避免浮点截断和 DPI 缩放偏移。
每个字形提交后先 flush，再复用小纹理；异步分块期间保留完整绘制命令，
缩放窗口时重新开始当前帧，替换纹理或销毁窗口时取消待完成绘制。
字体重载重新绑定句柄，纹理池有固定上限，绘制索引检查范围；逐条命令
仅提交对应顶点跨度，避免 SDL 队列复制整帧。低内存装饰缓存上限 512KiB。

Live2D Vulkan 普通与遮罩参数缓冲按首次实际绘制分配，隐藏部件不再
预先占用普通参数缓冲；映射失败销毁部分资源并恢复空状态，允许重试。
没有关闭 Vulkan 管线优化来换取内存，保持驱动默认优化。

以下为历史测试，不能代表恢复键盘和字体清晰度后的当前版本。

2026-10-13，同一 gamepad 模型、低内存模式、设置窗口打开，11 秒测量：

| 后端 | 专用工作集 MiB | 私有提交 MiB | 总工作集 MiB |
| --- | ---: | ---: | ---: |
| OpenGL | 44.2 | 63.1 | 125.7 |
| Vulkan | 44.9 | 64.8 | 127.9 |

专用工作集包含设置窗口，但不是总工作集或私有提交。该结果只适用于
当前机器、模型及已测设置页面；不能承诺所有模型、驱动、设置页面或
多桌宠都在 50MiB 以下。未使用工作集裁剪、强制换页或另起进程隐藏占用。

35 秒复测（两个后端分开运行）：OpenGL 专用工作集 44.3MiB、
私有提交 63.6MiB；Vulkan 专用工作集 45.9MiB、私有提交 64.0MiB。
两者设置界面诊断 valid=1，自动退出状态为 0。

恢复完整键盘素材与实际字号后的 standard 模型测试（包含设置窗口）：
Vulkan 专用工作集约 48.2MiB，OpenGL 约 61.2MiB，仍未达到 45MiB 目标。
这组数据测于最终字体采样调整之前；不同模型发现路径与交互可能影响比较。
不以历史 gamepad 数据或模糊字体版本作为最终达标依据。

Vulkan 上传背景时已复制到独立 staging。低内存模式在确认后端持有相同
尺寸/修订的副本后释放 CPU 合成画布；背景素材、几何或设备变化时重新
生成，原始键盘和背景素材始终保留。堆回收在活动结束 250ms 后合并执行，
不逐帧裁剪工作集。音效 50 个声部仅在引擎初始化时分配；先停止声部并
关闭音频线程，再释放声部池，空闲状态不保留该池。
